# Cosmos Engine

Небольшой рендерер на Vulkan, написанный с нуля на голом C API — без
`vulkan-hpp`, без `volk`, без `vk-bootstrap`. Вырос из пошагового изучения
Vulkan: сначала руками разбиралась каждая деталь, потом из этого собралась
архитектура.

Название с оговоркой: это **renderer**, а не game engine. Движком вещь
становится, когда обслуживает контент, созданный не программистом —
сцены из файлов, ассеты без правки кода. Дойдём и до этого (см. дорожную
карту), но обещать заранее нечестно.

## Что уже умеет

- Vulkan 1.0 на голом C API, слои валидации в debug-сборке
- Выбор GPU по возможностям, логическое устройство и очереди
- Swapchain, render pass, graphics pipeline
- Буфер глубины, MVP-матрицы, свободная камера (WASD + мышь)
- Текстуры: staging, layout-переходы барьерами, мип-пирамида, анизотропия
- Управление видеопамятью через VMA: суб-аллокация, выбор памяти
  по намерению вместо ручного перебора типов

## Требования

Linux, компилятор с поддержкой C++23 (проверено на GCC 14), CMake 3.16+:

```bash
sudo apt install cmake g++-14 libvulkan-dev vulkan-tools vulkan-validationlayers \
     libglfw3-dev glslang-tools libvulkan-memory-allocator-dev libglm-dev \
     libstb-dev pkg-config
```

Проверка окружения: `vulkaninfo --summary` должен показать GPU,
`vkcube` — крутящийся кубик.

## Сборка

```bash
cmake -B build -DCMAKE_CXX_COMPILER=g++-14
cmake --build build
./bin/cosmos
```

Шейдеры компилируются вместе с кодом: правишь `.vert` — следующая
сборка сама обновит `.spv`.

## Ассеты

Текстуры и модели в репозиторий не входят: бинарник, попавший в историю
git, остаётся в ней навсегда и раздувает клон. Поэтому папку `textures/`
нужно наполнить самостоятельно.

Сейчас движок ждёт один файл — `textures/pottery_basecolor.jpg`. Подойдёт
любая квадратная картинка, например с [Polyhaven](https://polyhaven.com/textures),
[ambientCG](https://ambientcg.com/) или [Poliigon](https://www.poliigon.com/);
достаточно переименовать её. Без файла движок не запустится и честно
скажет, чего именно не нашёл.

Дальше по дорожной карте понадобятся и остальные карты материала —
`_normal`, `_roughness`, `_metallic`, `_ao`. Наборы с такими картами
раздают все три сайта выше.

## Архитектура

Код разделён по **времени жизни** ресурсов, а не по типу вещей.
Зависимости идут только вниз: `core/` ничего не знает про Vulkan,
`vk/` ничего не знает про сцену.

```
core/    Window, Camera, Input                  без единого упоминания Vulkan
vk/      Context, Swapchain, Allocator, Buffer, Image, Commands,
         RenderPass, Pipeline, Shader, Descriptors
render/  Renderer, Mesh, Texture, Frame
scene/   Vertex
```

Владение однозначное: каждый ресурс принадлежит ровно одному объекту
и освобождается его деструктором. Копирование запрещено, перемещение
разрешено. Порядок разрушения задаётся порядком объявления полей —
никакого ручного `cleanup()`.

Сознательно не используются: RHI-абстракция (спрятала бы Vulkan, который
и есть предмет изучения), синглтоны (ломают порядок разрушения),
интерфейсы «на будущее».

## Библиотеки

Принцип: сначала руками, потом библиотека. Библиотека ценна тогда, когда
понятно, от какой боли она избавляет — подключить раньше значит потерять урок.

| | |
|---|---|
| GLFW | окно и ввод |
| GLM | векторы и матрицы в стиле GLSL |
| stb_image | загрузка картинок |
| VMA | управление видеопамятью — после того, как аллокация была написана руками пять раз |
